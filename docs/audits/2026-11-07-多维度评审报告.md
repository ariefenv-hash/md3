## 1. 总体结论（先说好消息）

1. **52 应用冷启动 + 开关压测：0 pageerror、0 console error、0 卡死**。#225 的修复（v10.33/v10.36）在「开→关→急开」压测路径上全部通过，launchScreen 均正常释放（opacity=0）、iframe 几何均为 900×1010 满幅。
2. **线上即最新**：https://ariefenv-hash.github.io/md3/ 的 precache-manifest 与本地 v10.36 dist **逐条目一致**（173/173，零缺失零腐化残留）。#235 描述的「Pages 零上线」窗口已恢复。用户此前在线上看到的现象，若发生在 11-05 之前，很可能是旧版本产物；当前版本无法复现「只显示按钮、内容不可操作」级失效。
3. **数据打通面健康**：phone↔contacts 共享 `md3_contacts` 单源；appstore↔installer 走 `__pkgInstallerAPI` 单一真源；page-stack 的定时器接管是 bg-freeze 冻结中心的刻意设计（不是泄漏）。
4. **动效偏好覆盖良好**：`prefers-reduced-motion` 全库 80 处；`color-mix` 169 处中无兜底的仅 1 处（#211 治理有效）。
5. 主题注入三通道（style 注入 + inline 直写 + postMessage）在 iframe 装载器里实现完整。

## 2. 用户点名问题的核验结果

### 2.1 「某应用重大失误，只显示按钮、内容不可操作」
**v10.36 全量实测未能复现**（两轮探测 + 压测均干净）。症状与 #225（已修，pending-verification）完全同构；若用户最近仍在线上遇到，请提供具体应用名与操作序列，可定向复测。注意：若设备命中 SW 旧缓存（cacheFirst 策略），可能仍跑旧代码——建议在应用内做一次强刷新后再核。

### 2.2 「国际象棋最小可执行感 + 有 bug」——**实锤，见 #236**
运行时取证：AI 思考窗点「新局」→ 新局被幽灵走子 `Nc3` 且随后**死局**（轮黑方、人机模式玩家执白无法行动、AI 不会被触发，SAN 永久冻结）；思考窗切「双人」→ pvp 模式幽灵替黑方走子；升变恒自动升后（核心支持四选择但 UI 无弹窗，DOM 内无任何升变元素）；中局深度 3 主线程阻塞 517ms（无 Web Worker，中端手机预计 1~2s 冻结）；AI 零随机性（同局面确定性→镜像走法必得同一局）。规则边角：KBvKB 异色格象被误判自动和棋（node 实测 `insufficient`，FIDE 下该局面可辅助将杀）。e2e-v132 六条断言覆盖不到以上任何一条。

### 2.3 「应用内功能重叠」
通讯群（phone↔contacts 共源）、安装链（appstore↔installer 单真源）**已打通**，重叠问题集中在 #177/#178 已立案范围；本轮新发现的重叠有限，主要缺口是 messages/mail 不读 `md3_contacts`（#214 已含预编联系人话题，作为其延伸注记，不另立案）。

### 2.4 「设计语言有没有贯彻落实」——**量化实锤，见 #238**
全库 **56 种不同 cubic-bezier 曲线并存**（Top3：`0.2,0,0,1` ×102、`.34,1.56,.64,1` ×53、`0.2,0.8,0.2,1` ×18），而 `_shared/md3-tokens.css` **零运动令牌**（无 `--md-easing-*` / `--md-duration-*`）。MD3E 的 emphasized/generic easing 与 spring 体系没有令牌化落点，每个应用各自手写曲线——这是「设计语言未贯彻」的结构性根源，与 #227（滑块规格）、#229（动效密度）同根不同面。
