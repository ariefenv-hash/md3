# 命名叙事基线（#289 · 评估与裁决）

> 项目考证基线为 **AOSP android-17.0.0_r1**（#18 §1），但仓库存在三条互相不一致的名称轨道。本文给出语义分层与影响评估，**不改任何文件**。

## 一、三轨现状（实读）

| 轨道 | 位置 | 值 | 语义 |
|---|---|---|---|
| 包标识 | `package.json` `name` | `android16-geek` | npm 包 / 项目内部标识 |
| 品牌名 | 根 `index.html` `<title>` | `安卓16极客` | 面向用户的产品名（站点标题） |
| 考证叙事 | `ios-desktop/index.html` `<title>` | `md3 — Android 17 / Pixel 10 物理体验` | 移植基线说明 |

## 二、判定：三轨分属三个语义层，不应强行统一

1. **「16」是品牌残留，不是版本号声明**。根标题与包名是项目创立时的产品名（安卓16极客），改它会改动品牌、仓库外链文案、`README` / `worklog` / 文档引用，且与 npm 发布面无关（本包无发布依赖，但破坏性标识改动收益为零）。
2. **`ios-desktop` 标题是考证基线叙事**，写「Android 17」是**正确**的：它描述的是"对齐哪版 AOSP"，不是产品名。把三处都改成 17 反而会让"产品名"与"移植基线"混淆。
3. 真正的问题是**零文档化** —— 新读者会以为三处写错了。因此处置为**成文，不改字**。

## 三、处置建议逐条裁决

| 议题建议 | 裁决 | 理由 |
|---|---|---|
| ① 文案统一为 A17 叙事 | **不采纳** | 品牌名与考证基线是两个语义层，强行统一会丢失品牌且制造混淆 |
| ② package name 改动影响评估 | **已完成 → 保留** | 无 npm 发布依赖；改动波及 worklog/docs/README 引用面，收益为零、风险非零 |
| ③ `check:version` 校验两处 title 版本字样一致 | **判定不适用** | 实读 `scripts/audit-version-consumers.mjs`：**不消费 `<title>`**；两处 title 内均不含 `vX.YZ` 版本真源串。加校验会变成"校验两个本不该相等的值"，与门禁语义冲突 |

## 四、约定（后续遵守）

- 新增**面向用户**的文案：用品牌名「安卓16极客」，不写版本号。
- 新增**考证/移植说明**：写「AOSP 17 / Android 17」，不写品牌名。
- 新增**包/仓库标识**：沿用 `android16-geek`，不随基线版本滚动。
- 若将来决定改品牌名：须单独立卡，同步清点 `README.md` / `docs/worklog.md` / `manifest.webmanifest` / SW 缓存名 / 站点外链文案，并评估版本真源门禁影响。
